## 2. 핵심 주제

### 2-1. 개발자의 기본 역할
개발자는 단순히 코드를 작성하는 사람이 아니라 문제를 해결하는 사람입니다.

핵심 역할:
- 요구사항 이해
- 문제를 설계로 변환
- 구현
- 테스트
- 배포 및 유지보수

중요 포인트:
- 코드 작성 속도보다 문제 해결 능력이 중요
- 기능이 동작하는 것만이 아니라 유지보수 가능해야 함
- 협업을 고려한 코드 작성이 중요함

---

### 2-2. 프론트엔드와 백엔드의 차이

#### 프론트엔드
- 사용자가 직접 보는 화면을 구현
- HTML, CSS, JavaScript/TypeScript
- UI/UX, 반응성, 접근성 중요

#### 백엔드
- 서버, 데이터 처리, 인증, 보안 담당
- API 설계, DB 연동, 비즈니스 로직 구현
- 성능, 확장성, 안정성 중요

#### 실제 실무 관점
- 프론트는 화면 경험
- 백엔드는 서비스 동작
- 둘을 연결하는 API가 핵심

---

### 2-3. 개발 환경 구성

필수 도구:
- IDE: VS Code
- 버전 관리: Git
- 패키지 관리: npm / pnpm / yarn
- 실행 환경: Node.js
- 협업 툴: GitHub, Notion, Jira, Slack

설치 및 운영 팁:
- 프로젝트마다 Node 버전 통일 필요
- lock 파일은 협업 시 필수
- .env 파일은 비밀정보 보관용으로 별도 관리

## 3. 프로그래밍 기초

### 3-1. 변수와 자료형
```ts
const userName = "홍길동";
const age = 25;
const isActive = true;

console.log(userName, age, isActive);
```

개념 정리:
- 변수는 값을 저장하는 공간
- 문자열, 숫자, 불리언은 기본 자료형
- 배열, 객체는 복합 자료형

### 3-2. 함수
```ts
function greet(name: string) {
  return `안녕하세요, ${name}님!`;
}

console.log(greet("민수"));
```

중요 포인트:
- 함수는 재사용 가능한 코드 블록
- 입력값과 결과값을 명확히 정의
- 하나의 함수는 하나의 역할만 담당하는 게 좋음

### 3-3. 조건문과 반복문
```ts
const score = 80;

if (score >= 90) {
  console.log("A");
} else if (score >= 70) {
  console.log("B");
} else {
  console.log("C");
}
```

```ts
for (let i = 0; i < 3; i++) {
  console.log(i);
}
```

이유:
- 조건문은 분기 처리
- 반복문은 같은 동작을 여러 번 처리

## 4. 웹 개발 핵심

### 4-1. HTML, CSS, JavaScript

#### HTML
- 문서 구조를 표현
- 제목, 본문, 버튼, 입력창 등 구성

#### CSS
- 시각적 스타일 적용
- 레이아웃, 색상, 간격, 반응형 디자인

#### JavaScript
- 동작과 로직 처리
- 클릭, 입력, API 호출, 화면 갱신

### 4-2. React의 개념
React는 UI를 컴포넌트 단위로 구성하는 라이브러리입니다.

예시:
```tsx
function Button() {
  return <button>클릭</button>;
}
```

장점:
- 재사용성
- 유지보수 편의
- 상태 기반 UI 업데이트

핵심 개념:
- 컴포넌트
- Props
- State
- 렌더링

## 5. 백엔드 기본

### 5-1. API의 역할
API는 프론트엔드와 서버가 데이터를 주고받는 통로입니다.

예시 흐름:
1. 사용자가 버튼 클릭
2. 프론트엔드가 API 호출
3. 서버가 데이터 처리
4. 응답을 받아 화면 갱신

### 5-2. 데이터베이스
DB는 정보를 저장하는 장소입니다.

대표적인 종류:
- MySQL
- PostgreSQL
- SQLite
- MongoDB

기본 개념:
- 테이블
- 컬럼
- 행
- 관계

### 5-3. 인증과 보안
중요 요소:
- 비밀번호 해시 처리
- 세션/토큰 기반 인증
- 입력값 검증
- XSS, CSRF 대비

보안은 기능 구현 이후 반드시 점검해야 합니다.

## 6. 협업과 Git

### 6-1. Git의 기본 개념
Git은 코드 변경 이력을 관리하는 도구입니다.

주요 명령:
```bash
git init
git add .
git commit -m "초기 커밋"
git branch
git checkout -b feature/login
git push origin feature/login
```

### 6-2. 브랜치 전략
- main: 배포용
- develop: 개발 통합
- feature/*: 기능 개발
- hotfix/*: 긴급 수정

### 6-3. 코드 리뷰
- 기능이 맞는지 검토
- 코드 품질 점검
- 유지보수성 확인
- 협업의 핵심 요소

---

## 7. 테스트와 품질 관리

### 7-1. 테스트 종류
- 단위 테스트: 함수 단위 검증
- 통합 테스트: 모듈 간 동작 검증
- E2E 테스트: 실제 사용자 흐름 검증

### 7-2. 왜 테스트가 중요할까?
- 버그 감소
- 안정적 배포
- 수정 범위 예측 가능

### 7-3. 코드 품질 팁
- 함수와 변수 이름을 명확히 작성
- 중복 코드를 줄이기
- 주석은 과도하게 쓰지 않기
- 작은 단위로 나누어 개발하기

## 8. 실무에서 많이 쓰는 개발 습관

### 좋은 습관
- 작은 단위로 커밋하기
- 의미 있는 커밋 메시지 작성
- 주석보다 가독성 높은 코드 작성
- 에러 로그를 확인하고 원인 파악하기
- 문서를 남겨서 협업 효율 향상

### 나쁜 습관
- 기능만 구현하고 끝내기
- 예외 처리를 빼먹기
- 의미 없는 변수명 사용
- 디버깅 없이 수정 반복

---

## 9. AI 활용 실무 가이드

### AI에게 요청할 때 좋은 방법
- 작업 목적을 명확히 설명
- 입력 데이터와 제약 조건 포함
- 결과물을 원하는 포맷으로 요청

예시:
```text
이 함수는 사용자 로그인 로직을 처리합니다.
TypeScript로 작성하고, 에러 처리를 포함해 주세요.
JWT 기반 인증을 가정하고, 코드 설명도 함께 부탁드립니다.
```

### AI 활용 시 주의점
- AI 생성 코드는 항상 검토해야 함
- 보안 취약점이 없는지 확인
- 프로젝트 구조와 스타일에 맞게 수정
- 테스트 코드를 함께 검토

AI는 속도와 생산성 도구이지, 책임을 대신하지는 않습니다.
